# Ф0б · проверка полноты диагностики

## Опечатка в имени клипа даёт успешную проверку

Проверяющий агент собирался сравнить трюк Полюсика с принятыми кадрами. Три настоящих вызова из `tools/creatures` с `--check --jobs 1` дали следующий результат. Ни одна команда не изменяет эталоны. [Журнал вызовов](snap-coverage.json)

| Имена клипов в `npm run ws -- snap pocket_magnet … --check --jobs 1` | Кадров в отчёте | Код завершения |
| --- | ---: | ---: |
| `trcik` | 0 | 0 |
| `trick` | 166 | 0 |
| `trick trcik` | 166 | 0 |

Ввод с одной опечаткой печатает «✓ pocket_magnet: 0 frames identical». Смешанный случай нельзя поймать требованием «сравнили хотя бы один кадр». Программа выбирает из известных анимаций те, которые совпали с запросом, затем сравнивает известные имена и возвращает успех при пустом списке различий. См. [snap.ts, фильтр определения](../../../tools/creatures/studio/snap.ts#L153), [фильтр сравнения](../../../tools/creatures/studio/snap.ts#L173), [проверка результата](../../../tools/creatures/studio/snap.ts#L234).

**Масштаб и ущерб.** Условие уже воспроизводится в одной работе. При удачно написанных именах контроль с 166 кадрами срабатывает. Частота опечаток среди агентов неизвестна. При ручной выборочной проверке вследствие одной ошибки можно вообще не увидеть изменившийся клип и передать технически зелёный результат владельцу. Полная проверка без списка клипов идёт другим путём.

**Предложение для Ф3/Ф4.** До рендера сравнивать весь запрос с множеством имён картины и явно перечислять отсутствующие имена, в том числе при частично корректном запросе. В опыте ТЗ для `trick` остаётся 166 кадров и успех, два запроса с `trcik` должны завершаться неполным покрытием. В мастерской ничего не изменено. Поиск по словам «опечат», «несуществующ», «0 frames», «пустая проверка», «ноль кадров» в [lessons.md](../../../.agents/skills/pixel-bosses/references/lessons.md) и [gate.ts](../../../tools/creatures/studio/gate.ts) совпадений не дал. Это наблюдение о диагностике; живопись Полюсика в этом опыте не оценивалась.
