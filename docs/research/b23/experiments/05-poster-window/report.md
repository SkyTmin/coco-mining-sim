# Опыт 05. Сколько обложек нужно удерживать для одного экрана

**Решение для проекта.** При 300 записях можно удерживать до 16 холстов с растровыми обложками в этой геометрии экрана. При пяти положениях прокрутки все 60 видимых сравнений с исходным способом дали те же ID и SHA-256 RGBA. Это обосновывает пилот ограниченной загрузки для стены; актуальный объём собственной памяти телефона и стоимость большого общего листа остаются отдельными измерениями. Художественный стиль и содержание картин в опыте не менялись. [Числа и хеши сравнений](results/run.json) · [Ф0б с настоящим проигрывателем](../../scale.md)

Выполнена заранее записанная гипотеза об ограниченном количестве поверхностей. В изолированной HTML-странице отображаются обложки из реального объединённого листа 41 принятых работ. Для восьмёрки взяты ровно восемь работ Ф0, для 100 и 300 записей повторяется состав 41. Исходная версия стенда держит холст каждой записи. Вторая выделяет холст для строк в экране и возле него; DOM списка сохраняется. Обе читают одну текстуру. Сравнение сделано на `d6ebb31`, Linux, Chromium 156.0.8078.79, DPR 2, 390×844 CSS-пикселя, GPU отключён, CPU0. Перед каждой сменой варианта — новый браузерный контекст. [Стенд и протокол](https://github.com/SkyTmin/coco-mining-sim/tree/chatgpt/b25-experiments/docs/research/b23/experiments/05-poster-window)

У восьми картин все работы помещаются на экране; оба способа расходуют одинаковое число байтов холстов. У 41 за пять положений новый способ рисует на 22 раза больше из-за повторного создания. У 300 разница двух максимумов по холстам составляет 60 143 840 байт (около 57,36 МиБ). Общие изображения постеров, декодирование, DOM и страницы актёра исключены из этого вычитания. Корневой массив сетки растёт с каталогом. Измерен один браузер, который делил ресурсы с другими задачами. На исходной стене из 300 записей первый вызов обновления занял 498,3 мс; на ограниченной стене максимальное обновление в пяти положениях заняло 45,6 мс. После готовности исходной стены переключение между позициями не требовало повторной нарезки. Подбирать лимит в миллисекундах для телефона по этому запуску нельзя.

Для повторения получить зафиксированный репозиторий, установленный Chromium, Python с Playwright и код отдельной ветки. Из каталога опыта запустить `python src/run.py /path/to/d6ebb31 results/run.json --chromium /usr/bin/chromium`. Отчёт хранит контрольные отпечатки видимых элементов на каждом положении скролла. Исполняемые исходники остаются в ветке опытов.
