# Предрегистрация. Проверяемый охват `snap --check`

**Гипотеза.** Передача точного множества пар «картина/клип» и ожидаемых длин в проверку выявит ложный успешный результат при опечатке, смешанном запросе и пустой выборке. На валидном запросе список сравниваемых кадров и исход сравнения должны сохраниться. Это проверка качества инструмента для проектов, соответствующих ориентиру владельца из DECISIONS от 28.11; художественный материал не изменяется.

**Единицы.** Базовая восьмёрка Ф0 на замороженном `d6ebb3145d47d6bed85b088ec30b0b2faa82da6f`. У обновлённого Полюсика `cced294` будет отдельный контроль. Штатная команда — `node --import tsx studio/ws.ts snap <id> [clips…] --check --force --jobs 1`. Для отдельных живых участников брать имена и длительности из загрузчика картины, `frameCount(seconds)` и множитель `lifeCycleCount` для `life`. Независимая проверка количества и принадлежности кадров — словарь массивов `golden/<id>.json`. Эталон не перезаписывать. Текущий архив одного настоящего вызова уже показывает, что `trcik` даёт успешное сравнение нуля кадров, а смесь `trick trcik` — успешное сравнение только существующего трюка. **Порядок.** Сначала взять данные из принятых файлов и штатного пути. Затем составить намерение прохода отдельно от его результата. Для ошибочного запроса поставить счётчик входов в callback вычисления изображений. Успех для кандидата требует ноль входов у каждого из трёх классов невалидного запроса до создания пула расчёта кадров. Время чтения описаний и построения индекса учесть отдельно. Успех для валидного запроса требует совпадения ID, имён, количества кадров и поведения компаратора. Перестановка имён и дубликаты не должны влиять на множество. Кандидат экспериментальный, вызывается из каталога опыта.

**Цена.** На одном CPU измерить стоимость холодной подготовки каталога, повторное построение решения по готовому индексу и штатные затраты на один `idle`. Для дешёвого решения показывать медиану и 95-й процентиль нескольких серий, указав размер серии, число запусков и единицы. Для долгой реальной команды отдельно фиксировать wall time, код завершения и число подтверждённых кадров; не экстраполировать на целый инструмент. Если отстрел невалидной смеси экономит время, не переносить такой выигрыш на нормальную работу без опечатки.

**Критерий результата.** Зафиксировать все расхождения и цену валидного пути. Прохождение здесь поддерживает опытный контракт охвата; решение о Ф5 остаётся за Claude. Общая сетка проверок, художественное качество, полнота числа `golden` и UI‑поведение — другие метрики. Реализация только в `src/` этой папки опыта, JSON в `results/`, отчёт в `report.md`.
