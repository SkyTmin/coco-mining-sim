# Ф3-07. Видны ли расход и след на экране после смены клипа

В Chromium на первом кадре отдыха Полюсика успешный и отклонённый исходы отличались **15 пикселями** в технической отметке следа. После скрытия слоя экранные снимки двух разных состояний совпали попиксельно. Новая страница восстановила оба состояния из localStorage и повторила оба снимка. Штатный атлас и его исходные пиксели использованы без изменений. [Измерения](results/browser.json) · [Протокол до запуска](protocol.md)

## Показ и контроли

Использован принятый Полюсик из ревизии `60affec40c74f81e8ce886400ea3b07c0d8f5911`. На локальной изолированной странице Chromium 156.0.8078.79 исходные загрузчик материалов и тело метода `Painting.draw` прочитаны из этой ревизии. Полные блоки кода переданы браузеру в тестовом модуле без изменений. В стенде отсутствуют навигация и DOM штатной стены. По сети внутри loopback действительно прочитаны atlas.json, behavior.json, страницы актёра p-0.webp и p-1.webp, слой сцены, рамка и её тайлы. SHA-256 запрошенных байтов сохранены. Внешние запросы для показа не требуются. [Штатная сборка кадра](https://github.com/SkyTmin/coco-mining-sim/blob/60affec40c74f81e8ce886400ea3b07c0d8f5911/tools/creatures/viewer/viewer.mjs#L359) · [Фактически прочитанные файлы](results/browser.json)

Штатное поведение на seed 7319 получило `skill_ready` раз в 360 тактов. На такте 503 показан кадр 110 `trick_b`, на такте 504 пришёл отмеченный контакт на кадре 111, вхождение № 13. На такте 573 начался `idle`, кадр 0. Три прочитанных RGBA различны. Две ветви получили один и тот же внешний ввод и разделяли нативную траекторию, отдельно хранили 1 и 0 заряда. При одном заряде правило Ф3-01 записало `charge=0, changed=["star-socket"], applied=[13]`; при нуле оставило пустые списки. Это условие эксперимента. [Правило и отрицательные контроли Ф3-01](../01-state-price/report.md) · [Реальные сэмплы, операции и хеши](results/browser.json)

Собранное родное изображение копировалось на экранный canvas. В тестовом слое запасу отведены 5 × 4 пикселя с левым верхним углом (12,12): при одном заряде они бирюзовые, при нуле красные. Отметка `star-socket` занимает 5 × 3 пурпурных пикселя с углом (145,118). Поле картины 160 × 128, весь canvas с рамкой — 176 × 144. В окне браузера он имел ровно 176 × 144 CSS-пикселя при DPR=1. Пиксельные разности посчитаны по RGB двух снимков экрана внутри границ canvas. Отдельная проверка сравнивает SHA-256 RGBA непосредственно через Canvas API. [Код вывода](https://github.com/SkyTmin/coco-mining-sim/blob/chatgpt/b25-experiments/docs/research/b23/experiments/07-browser-state/src/stand.mjs) · [Результаты](results/browser.json)

Во всех строках ниже используется один кадр `idle/0` на такте 573. Первая строка показывает две версии состояния на *одном* кадре отдыха. Это устраняет движение персонажа и сценового света из измерения.

| Пара снимков | Расход, пикс. | След, пикс. | Вне двух участков |
|---|---:|---:|---:|
| Ветка с зарядом, исходное состояние → применённое | 20 | 15 | 0 |
| Пустая ветка, до → после отказа | 0 | 0 | 0 |
| Допустившая и отклонившая ветви после контакта, слой включён | 0 | 15 | 0 |
| Те же разные состояния, слой выключен | 0 | 0 | 0 |
| Первая команда → повтор того же вхождения, отдельно по каждой ветви | 0 | 0 | 0 |
| Состояние в исходной странице → восстановленное в новой, отдельно по каждой ветви | 0 | 0 | 0 |

Повтор того же контакта в успешной ветви вернул `duplicate`, повтор в пустой — `insufficient`. Нативный RGBA всех вариантов кадра 573 одинаков: `3367ea4146db912c83e75b8f2eeaf519b6a8ea36af214dcb114fbde8026ca78c`. При спрятанном слое конечный RGBA также равен нативному. Вторая страница внутри того же browser context заново вычисляла ход поведения при том же seed, но брала конечные записи состояния именно из localStorage. Это проверяет восстановление на том же origin устройства в пределах сессии. [Двенадцать экранных снимков по хешам, восемь попарных проверок](results/browser.json)

## Слепая проверка кадра

Независимый проверяющий получил четыре экранных PNG с нейтральными именами до чтения программы и карты условий. В ×1 он узнал бирюзового героя с магнитом, звезду и лоток. По последовательному просмотру он не смог уверенно различить пары и назвать отдельное новое действие. Независимым чтением PNG через Pillow он нашёл 0 из 25 344 различающихся пикселей в паре ash–birch и 15 в elm–fir: прямоугольник x=145…149, y=118…120. У fir в нём RGB (252,27,217), у elm виден деревянный пол. После фиксации ответа раскрыто, что у первой пары разные записи состояния при скрытом слое; во второй fir относится к разрешённой ветви. Один просмотр не измеряет общую распознаваемость, но прямо показывает, что обнаруживаемый инструментом сигнал ещё не передал этому наблюдателю смысл действия. ## Граница для Ф4

Для проекта достаточно предусмотреть чтение состояния после привязки к конкретному контакту, вывод этого состояния поверх воспроизводимого кадра и возможность снять аппаратный снимок при выключенном слое. В проверенной конфигурации расход и след различимы по машинной разности; повтор и восстановление детерминированы. Из опыта нельзя вывести зрительское понимание смысла отметок, художественное качество следа, его доступность на телефоне или наличие такого контракта в выпускаемой галерее. В опыте одна принятая работа, один контакт, одна новая поза, один seed и одна версия браузера. [Изолированная методика](protocol.md)

## Повторение

В каталоге опыта на ветке `chatgpt/b25-experiments`, с доступом к Git-объекту указанной ревизии, Chromium, Python, Playwright, Pillow и NumPy:

```sh
python src/run.py --repo "$(git rev-parse --show-toplevel)" \
  --state-src ../01-state-price/src --results /tmp/browser-state.json \
  --images /tmp/browser-state-shots
```

Параметр `--images` сохраняет 12 исходных PNG для просмотра; без него снимки находятся во временном каталоге и удаляются после расчёта. В JSON остаются хеши, поля состояния, положение прямоугольников разности и список сетевых чтений. [Код измерения](https://github.com/SkyTmin/coco-mining-sim/blob/chatgpt/b25-experiments/docs/research/b23/experiments/07-browser-state/src/run.py)
