# Ф1. Как карточка становится кадром галереи

У Полюсика авторский код собирает тело и эффект для каждого кадра при экспорте. В браузере ту же картину показывает проигрыватель готовых слоёв. У Крысиного короля браузер загружает отдельный рисовальщик и сам рассчитывает позы. Оба пути открыты по обычной ссылке галереи в Chromium 156.0.8078.79. В каждом зарегистрировано как минимум пять переносов изображения на главный холст, ошибок страницы и HTTP ≥400 за время наблюдения не было. Это подтверждает два пути вывода, а попиксельное совпадение со всем экспортом остаётся отдельной проверкой. [Протокол браузера](measurements/trace-viewer.json) · [Программа](measurements/trace-viewer.py)

Ревизия исходников замеров — дерево Git `802379ea59f2275d34d7ab1fbcb6e949dbf63d61` каталога `tools/creatures` в коммите `c1eaf999c09d53ff72385721ddb09eaff1949b62`. Пути и строки ниже отсчитываются от этого каталога. Размеры в строках включают комментарии и пустые строки отслеживаемых TS-файлов. Всего 120 825 строк. Данные каталога, картинки, Python, JavaScript исполнения и npm в это число не включены. [Инвентаризация](measurements/source-inventory.json) · [Исходники ревизии](https://github.com/SkyTmin/coco-mining-sim/tree/c1eaf999c09d53ff72385721ddb09eaff1949b62/tools/creatures)

## Что вызывает что

| Переход | Данные и проверенный участок |
| --- | --- |
| Описание → авторский модуль | Схема и дополнительные проверки карточки находятся в `studio/card.ts:21,36,58`. Команда черновика `studio/new.ts:130` пишет модули, связывает карточку с телом и книгой приёмов. При загрузке `c/pocket_magnet.ts:6` и `c/astral_seer.ts:8` читают свои данные. Есть авторские реализации, например `c/crater_titan.ts:146,727` строит и возвращает кадр своей функцией. Генератор черновика не вызывается на каждый кадр. |
| ID → картина | `render.ts:53–75` загружает модуль по ID, сверяет `c.id`, подмешивает настройку времени импакта, подбирает тему и индивидуальную/общую раму. При наличии файла life подключает план движения; при наличии еще и поведения подключает поведенческую машину. Отсутствие одного файла меняет маршрут. |
| Время → поза, сокеты, эффекты | `engine.ts:260–335` получает траекторию от `motion.ts`, разводит запрошенные и проигрываемые клипы, вычисляет контакт и удержание, затем вызывает `c.frame`. Тело использует `rig/figure.ts`, `rig/f15-rig.ts` или специальный риг картины. `fx/pen.ts:47` даёт инструменты рисования, `fx/sim.ts:189` — выборку симуляции для подключивших её эффектов. Подключение физики зависит от картины и клипа. |
| Слои → растр | `engine.ts:34,93,260` задаёт порядок десяти слоёв, композитор собирает фон, декорации, нижние эффекты, тело, его свет, верхние эффекты, общий свет, передний план, раму и выход за раму. `rig/px.ts:4` хранит RGBA, `engine.ts:59,83` накладывает цвет и свет. Есть поля и слои, оставшиеся пустыми в конкретном кадре. |
| Экспорт → упаковка | `render.ts:126–152,219,261` перебирает кадры с шагом 1/24, вызывает compose, пишет материалы и движение, наполняет GIF; `viewer-atlas.py:82,109,172` формирует атлас, `viewer_repack.py:27,106` переупорядочивает спрайты по первому использованию и пакует страницы WebP без потерь. Для просмотра существующей картины экспорт не нужен. |
| Каталог → экран | `gallery-catalog.ts:132,136` читает материалы и строит записи. `viewer/viewer.mjs:68,232,364,432–458,681` выбирает реализацию по runtime, загружает поведение/страницы, рисует сцену и накладывает слои, воду и лучи. `viewer/behavior.mjs` управляет реакциями. У Полюсика браузер получил actor-страницу `p-0.webp`, описание поведения и общую раму. Холст 176×144. [Запросы и результаты](measurements/trace-viewer.json) |
| Ревизия искусства → проверки | `studio/ws.ts:72,104,145` разводит пул, повторное использование прошедшей проверки и дополнительные проверки gate. `studio/snap.ts:70,79,151,205` хеширует готовый кадр, сравнивает с golden; `studio/review.ts:90` также использует штатный compose для визуального разбора. Это разные потребители одного результата. |

В Node v24.22.3 заново открыты два процесса. У Полюсика, trick 79, в данных покрытия 31 репозиторный TS/MJS-модуль, сработали `fishAt`, `tinFish`, `horseshoe`, `stack`. У Астрала, trick 57, 36 модулей, сработали `doubleOrbit`, `seerEffects`, `eyeClasp`, `stack`. Дайджесты сырых байтов RGBA начинаются соответственно на `338a463a` и `a22487ea`. В обоих записях присутствует собственный life-модуль, хотя запрошен trick: загрузка модуля сама по себе не доказывает вызов всех его функций. Показатели V8 включают имена, добавленные tsx, и анонимные функции отсутствуют в перечислении имён. Два независимых способа измерения дают разные единицы. Повтор исходного `source_inventory.py` дал тот же SHA-256 результата `b4700f1fe7681bc55eb869994703ea0c7fd6f0ac62c006ff7d33ac08c67341f2`: 407 различных повторных окон из восьми содержательных строк, покрывающих 2 108 позиций строк в файлах. Окна перекрываются. Это не 407 функций. Вторая программа сравнила тела именованных функций, сохраняя идентификаторы, числа, строки и пунктуацию, опуская комментарии и форматирование. В 241 файле, привязанном по имени к 41 golden, обработано 936 тел длиной ≥60 токенов; найдено 21 межавторское семейство, всего 62 вхождения. «Межавторское» здесь означает разные ID картин; один и тот же человек мог писать обе. Оба алгоритма пропускают смысловые аналоги с переписанной формулой. Второй также пропускает стрелочные функции, сравнение с переименованными переменными и обобщённые объявления. Это лексический проход, без разбора типов. [Окна строк](measurements/source-inventory.json) · [Функции](measurements/clone-functions.json) · [Сравниватель](measurements/clone-functions.py)

## Неиспользуемые объявления, параллельные пути и наследие

Найдены четыре локальных объявления, имя которых в токенах соответствующего модуля появляется только в объявлении. Ручная сверка подтвердила отсутствие экспортов, реэкспортов и строкового вызова: `band` в `c/astral_seer-skin.ts:63`, `limb` и `scutes` в `c/eclipse_drake-skin.ts:154,177`, `rotate` в `c/tuft_owlet-skin.ts:33`. Комментарий Зенита описывает чешуйки, но не вызывает функцию. Это четыре действительно неиспользуемые именованные функции текущего статического кода. Выборка ограничена именованными функциями и файлом по принятому ID. Для модулей, у которых нет вызова на двух показанных кадрах, утверждения о мёртвости нет. Ничего не удалялось. [Набор и аргумент](measurements/clone-functions.json)

При обычной картине экспорт и браузер оба собирают кадр с нуля из слоёв, однако исходные представления разные: экспорт вычисляет геометрию и положение, браузер читает готовые текстуры и дорожки. Для воды и лучей уже импортируются одни и те же функции в `engine.ts:5,6` и `viewer/viewer.mjs:1,2`. Упаковщики собственных и внешних картин также имеют разные входы, но оба вызывают `viewer_repack.py`. Замену обоих композиторов одним ещё предстоит оценить на разнице пикселей и стоимости загрузки.

Каторга несёт 21 604 строки TS, 1 609 MJS и 601 Python. Раннее происхождение не предсказывает, что из них выполняется сегодня. В `katorga/f1/source` успешно проверены все 12 записей `sha256sum -c ../SHA256SUMS` против сохранённого снимка `coco-instruments@523bae1`. `katorga/f1/build.mjs:15,31` выборочно вырезает участки оригинальных исходников и компилирует браузерный модуль; `katorga/f1/capture.py` записывает ролики через проигрыватель. `katorga/bosses/export.mjs`, `pack.py` и `check.py` относятся к отдельному офлайн-процессу экспорта. Нельзя по размеру исходного снимка вывести размер клиентской загрузки. [Инструкции и происхождение](../../../tools/creatures/katorga/README.md) · [Сборка F1](../../../tools/creatures/katorga/f1/build.mjs)

В каталоге этой ревизии 74 записи, из них 73 без специального runtime и одна с `runtime=f1`. Последняя — `rat_king`. В реальном браузере для неё дошли `king-painting.mjs`, `f1-native.mjs`, сцена короля и общая секретная рама, холст 675×564. Для Полюсика за тот же критерий первых пяти перерисовок эти два специальных модуля не запрашивались. Наличие TypeScript-картины короля и её golden не доказывает, что её вычисляет видимый клиент. Назначение исходного наследия установлено для сборки и одного реального runtime, отдельные недостижимые ветки исходного снимка не классифицированы. ## Время и память

Единственный проход Ф0 измерял выделенный CPU 2, диски общие, RSS снимался по группе процессов с периодом 0,2 с. Для восьми картин обычный экспорт idle с файлами и GIF потребовал 4,48–28,94 с и 243,2–618,0 МиБ. При первом срезе gate Полюсика потребовал 21,30 с / 944,6 МиБ, Астрала 87,36 с / 1 681,1 МиБ. Источник со всеми доступными gate и snap обновляется по окончании процессов; исторические количества golden-кадров не являются секундомером. Времена коротких опытов V8 с дополнительным сбором покрытия в эти цифры не включены. Для расходов внутри алгоритма нужны независимые профили и повторения. ## Повторение

Из каталога `tools/creatures`, с зависимостями текущей ревизии; во всех строках заменить переменную на путь к этому каталогу измерений:

```sh
D=../../docs/research/b23/measurements
python "$D/source_inventory.py"
python "$D/clone-functions.py"
node --import tsx "$D/trace-frame.mjs" pocket_magnet trick 79
node --import tsx "$D/trace-frame.mjs" astral_seer trick 57
python "$D/trace-viewer.py"
(cd katorga/f1/source && sha256sum -c ../SHA256SUMS)
```

Браузерная проверка использует Python Playwright и Chromium из окружения. Значение настроения и страницы, которые галерея успела предзагрузить, могут меняться со скоростью машины; устойчивые признаки маршрута — выбранный ID, модули реализации, размер холста и начало отрисовки. [Код проверки](measurements/trace-viewer.py)
