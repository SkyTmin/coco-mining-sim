# Нативные фазы на Linux, macOS и Windows

После проекта Ф4 сравниваем пиксели существующих произведений между тремя GitHub-hosted ОС. Из Ф0б известно, что на прежней Linux-машине у семи выбранных фаз prism_serpent результат зависел от версии Node. Опыт на трёх ОС фиксирует Node и материал. Различия между ОС могут также зависеть от архитектуры, системных библиотек и образов, поэтому результат относится к записанным конфигурациям. Художественную оценку он не заменяет.

## Вход и проверка

- Исходники продукта, golden и package-lock.json взяты из одного и того же d6ebb3145d47d6bed85b088ec30b0b2faa82da6f. Полюсик здесь в исходной версии Ф0; принятая позднее редакция cced294 — другая работающая ревизия, её результат на эти три ОС не переносится. Матрица запускается по push только ветки chatgpt/b25-research при изменении одного из четырёх путей: данного workflow, probe.mjs, compare.mjs или штатного sample-diversity.mjs. Сохранение JSON и отчёта отдельно не перезапускает дорогую серию.
- На GitHub-hosted ubuntu-24.04, macos-15 и windows-2025 ставится нативная Node v22.14.0 и выполняется npm ci --include=optional. Сэмплер хранится во втором checkout той же ревизии исследования во всех заданиях. Отчёт содержит фактические platform/arch, ABI, версии Node/npm/tsx/canvas, загруженный .node и его SHA-256, версию образа при её наличии, commit и отпечатки lockfile/сэмплера. Для двух текстовых файлов записывается хэш байтов на диске и хэш с едиными LF для сравнения между системами.
- Список 41 ID и порядок семи фаз задают golden. Рендер средствами существующего sample-diversity.mjs даёт четыре idle (0, 1/4, 1/2, 3/4) и три walk (0, 1/3, 2/3). Индекс равен целой части доли длины в golden. Фактический digest — первые 10 шестнадцатеричных цифр SHA-1 исходной RGBA-композиции, как в штатной выборке и golden. Это 40-битовая проверка, не абсолютное доказательство равенства картинок. В каждый отдельный вызов передаётся B25_RECORD_MISMATCH=1, чтобы первое отличие не уничтожило оставшиеся наблюдения.
- Временные PNG утилиты удаляются на runner. Наружу уходят только JSON и строки журнала. Глобальная установка проекта, изменения картин, запись golden и публикация галереи не требуются.
- Порядок и число файлов из job с погрешностью выборки проверяются до принятия результата. Полноценная пара требует совпадения входов и сравнения всех 287 адресуемых фаз. Для частичных данных выводим количество реально общих кадров и явную метку partial. При отсутствии модуля, раннера, отчёта или общих кадров видна метка not-comparable либо missing-report. Ни отсутствие результата, ни установка пакета не засчитываются за совпадение кадров.

## Вывод и повтор

Матрица не отменяет соседние задания при отказе одного runner. Каждая ОС пишет непосредственно в лог строку B25_PLATFORM_RESULT, передаёт маленький JSON общему job и сообщает об ошибках по ID. Общий job пишет строку B25_PLATFORM_PAIRS, считает три пары и загружает один JSON с исходными записями и сравнением в существующий черновик b25-research-evidence (ID 461736899). Перед вложением проверяются ID, тег и флаг draft. Имя файла содержит SHA исследования, run ID и номер попытки. Отказ доступа к Release оставляет исходные логи и промежуточные JSON. При повторе только отдельных jobs для строгого воспроизводимого сравнения предпочтителен «Re-run all jobs».

Для чтения журнала из авторизованного окружения:

```sh
gh run view RUN_ID --repo SkyTmin/coco-mining-sim --log | rg 'B25_PLATFORM_RESULT|B25_PLATFORM_PAIRS'
```

Для повторения на реальной ОС подготовить два checkout. Переменная CONTROL указывает на корень чистой копии d6ebb314, STUDY — на копию ревизии workflow с этими драйверами. Ниже приведён синтаксис Bash, включая Git Bash на Windows. Задать PLATFORM равным linux, macos или windows. Затем сопоставить полученные linux.json, macos.json и windows.json из общего каталога RESULTS.

```sh
set -eu
cd "$CONTROL/tools/creatures"
npm ci --include=optional --no-audit --no-fund
B25_OS="$PLATFORM" B25_NPM_VERSION="$(npm -v)" node "$STUDY/docs/research/b23/measurements/platform/probe.mjs" "$PWD" "$STUDY/docs/research/b23/measurements/scale/sample-diversity.mjs" "$RESULTS/$PLATFORM.json"
node "$STUDY/docs/research/b23/measurements/platform/compare.mjs" "$RESULTS" "$RESULTS/combined.json"
```

Отрицательные проверки сравнения — отсутствие целого отчёта, потеря одной записи, изменение эталонной декларации и один другой хэш при сохранённом адресе. Сигнал differences между ОС позволяет выбрать настоящую картину и фазу для отдельного исследования. Он не локализует причину в Skia/шрифтах и не измеряет её художественную заметность. Локальный запуск этих синтетических проверок не является запуском матрицы.
