# Вопрос 9. Как получить читаемую лестницу, сохранив краски художника

На восьми парах фактических цветов тела сравнили четыре способа построить семь ступеней. Между соседями измеряли расстояние ΔEOK уже после записи и чтения 8-битного кадра sRGB. Медиана относительного разброса шести шагов составила 0,008 для OKLab, 0,081 для обычной интерполяции кодов sRGB и 0,649 для линейного света. На выбранных парах OKLab пригоден как черновой генератор промежуточных чернил. Цвет лица, синяя тень и светящийся акцент остаются авторскими решениями. ## Данные, контроль, отрицательный результат

В выборке astral_seer, pocket_magnet, prism_serpent, frost_yeti, moon_magician, bramble_warden, bun_panda и storm_ram. Из слоя тела idle/0 выбраны реальные RGB на 10-м и 90-м процентиле распределения OKLab L среди пикселей с alpha ≥128. Это фиксированная выборка разных тел для проверки метода, а не перечень восьми эталонов Ф0. Два цвета могут приходиться на разные материалы. Chromium 156.0.8078.79 на Linux с выключенным GPU вычислил семь точек CSS color-mix; Canvas прочитан обычным RGBA8. Фактическое расстояние — евклидово в OKLab; коэффициент вариации равен стандартному отклонению шести расстояний, делённому на их среднее. Метрика по двум точкам не оценивает hue shift на собственной материальной лестнице, контраст с фоном, доступность цветовосприятия и мерцание. [Код](measurements/rq09/palette-study.py) · [Результат](measurements/rq09/palette-study.json)

| Пространство | Медиана разброса шести шагов | Несовпавшие крайние RGB из 16 | Где уместен контроль |
|---|---:|---:|---|
| sRGB, код канала | 0,08131 | 0 | Контроль действующих промежуточных чернил |
| Линейный sRGB | 0,64864 | 0 | Смешение количества света, когда это физический смысл операции |
| OKLab | 0,00815 | 0 | Промежутки между двумя авторскими опорными красками |
| OKLCH, короткая дуга | 0,01216 | 4 | Явно заданное направление оттенка и проверка результирующих байтов |

В частности, при весах цветов 0% и 100% в полярном режиме readback конечной светлой точки Астрала дал [241,242,249], хотя был задан [246,242,236]. Аналогичный эффект у четырёх из 16 концов. В трёх остальных режимах все концы совпали. Это наблюдение полного пути Chromium CSS → Canvas → RGBA8; причины конкретной реализации или стандарт этим тестом не установлены. В JSON также приведён разброс при принудительном восстановлении двух исходных крайних точек. В действующем Б22 чистый выбор индексов в `fit` уже сохраняет оба предела при n≥2 и индекс тени при n=1.
