## Контрпример для одной записи

Из пяти входов две правильные формы прошли, запись без обязательного поля и одновременно с двумя полями адресата были отвергнуты, строка с выдуманным именем сокета прошла. Это воспроизведено с Python и jsonschema 4.26.0. Существование сокета проверяет разрешитель ссылок или заранее построенный enum конкретного рига. Два по отдельности верных элемента одного массива ещё могут назначить владельца одному и тому же предмету дважды. Тест не проверяет такую коллекцию и не доказывает видимого контакта.

## Что сравнить в Ф3

Минимальный вариант добавляет проверку импортируемой карточки и целостности графа рядом с имеющимся ws events. Средний вводит единый адрес пространства и владения для нового клипа с адаптером старых данных. Дорогой импортирует физический движок или требует общего формата сразу у каждого автора. Заводить полную физику до измерения прототипа оснований нет: опубликованные шарниры решают только часть задачи. На одном и том же наборе вставить двойного владельца, потерю сокета и невидимые пиксели правильного контакта. Записать пропуски, ложные тревоги, время до диагноза и работу автора по исправлению. Эти варианты пока не приняты в проект Ф4.

## Воспроизведение опыта

Из каталога с временным файлом сохранить приведённый код как `probe.py` и выполнить `python probe.py`. В этой среде использован установленный jsonschema 4.26.0.

```python
from jsonschema import Draft202012Validator
def placement(kind, field):
    return {'type':'object','properties':{'kind':{'const':kind},field:{'type':'string','minLength':1}},
            'required':['kind',field],'additionalProperties':False}
schema = {'oneOf':[placement('held','socket'),placement('scenery','anchor')]}
v = Draft202012Validator(schema)
cases = [
    ('held', {'kind':'held','socket':'paw'}),
    ('scenery', {'kind':'scenery','anchor':'table'}),
    ('no-owner', {'kind':'held'}),
    ('two-owners', {'kind':'held','socket':'paw','anchor':'table'}),
    ('dangling-socket', {'kind':'held','socket':'not-a-socket'}),
]
for label, item in cases:
    print(label, v.is_valid(item))
```

## Поиск и граница насыщения

Выполнено 8 разных запросов. Прочитано 12 первоисточников в таблице. Последние три прочитаны после составления списка типов решений в указанной последовательности. Для исходного вопроса о месте проверки они повторили размеченный вариант, ограничение поля и ограничение степени свободы. Иные реализации возможны. Насыщение относится к выбору уровней контроля, а не к перечню всех физических ограничений.

1. `making illegal states unrepresentable Richard Minsky Jane Street state types Elm Richard Feldman domain modeling` — По исходной формулировке нашлись пересказы. Для самого доказательства использованы авторские руководства Rust / TypeScript с примерами вариантов.
2. `JSON Schema 2020-12 dependentRequired oneOf unevaluatedProperties constraints Khronos glTF validator sparse animation target` — Найдены схемы glTF, от исходной схемы перешли к опубликованному журналу кодов ошибок валидатора. Проверены NODE_LOOP и непорядок времени.
3. `Godot editor scene configuration warnings _get_configuration_warnings Unity OnValidate animation constraint editor` — Найдены обе документации редакторов. Godot сообщает предупреждение, Unity уточняет моменты вызова и ограничения исполнения.
4. `Rapier fixed joint limits rigid body allowed contact pair collision groups prismatic joint Box2D` — Найдены руководства Rapier по суставам и нескольким языкам. Прочитана Rust-версия, повторные переводы одной техники не считались независимыми.
5. `Bevy ECS hierarchy relationships ChildOf source despawn observer invariant animation invalid missing skeleton` — Найдена реализация Bevy hierarchy.rs. Проверены места, где ChildOf обновляет Children.
6. `数据 模式 约束 Godot 节点 配置警告 骨骼 编辑器 Blender driver dependency cycle constraints` — Китайский запрос дал в том числе документацию старой ветки Godot об экспорте скелета. Она не доказывает закрытие именно нашей ошибки.
7. `Yaron Minsky effective ML making illegal states unrepresentable design types Jane Street OCaml` — Поиск цитаты Минки дал преимущественно пересказы. Не приписывали ему непроверенный текст, для варианта со своими полями взят Rust Book.
8. `site:json-schema.org understanding dependentRequired if then else oneOf` — Официальная страница JSON Schema разбирает отсутствие обратной зависимости dependentRequired. Независимый пример CUE проверил ограничения чисел.
