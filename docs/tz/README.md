# ТЗ для Codex — как это устроено

- Одно ТЗ = один этап = одна ветка `stage-NN` = один PR в `main`. Следующее ТЗ начинается только после того, как Claude
  проверил этап по списку приёмки и слил PR [владелец 10.11: сливает Claude].
- Порядок этапов — таблица «План этапов» в конце этого файла (она заменяет `wiki/16` §2 после решений владельца 09–10.11).
  Сейчас готовы ТЗ этапов 0–2.
- В каждом ТЗ: цель простыми словами → что сделать (файлы, API, структуры, алгоритмы) → чего НЕ делать → приёмка
  (команды и тесты, которые должны пройти) → отчёт.
- Где ТЗ молчит, а вики говорит — прав ТЗ, если ТЗ прямо отменяет; иначе спроси в отчёте и сделай самое простое.
- Числа баланса — `docs/design/wiki/18-balans-chisla.md` (данные: `scripts/balance/data.mjs`). В ТЗ 0–2 числа — заглушки;
  с этапа 3 `scripts/design-decisions.json` заполняется из этих данных.
- Числа баланса в ТЗ помечены [решение] — это заглушки под симулятор, их ставят в `scripts/design-decisions.json`,
  а не в код.
