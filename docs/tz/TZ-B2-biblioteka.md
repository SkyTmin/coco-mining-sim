## 1. Руки в теле (сначала, отдельным коммитом)

`npm run ws -- gate all` на третьем пилоте: у Йети и Квакуньи ошибки `clip` (рука, дубина, посох уходят в корпус
и голову: Йети `tech_snowball` 17–29, `tech_slam` 6–16 и 19–25, `tech_icicles` 11–22, `tech_roar`, `happy`; Квакунья
`tech_croak`, `tech_tongue`, `tech_staff`, `tech_leap`, `tech_spores`, `phase`) и `hidden-contact` (удар закрыт
предметом переднего плана: Йети `tech_slam` 19, `tech_icicles` 32–38; Квакунья `tech_staff` 20, `tech_leap` 27,
`phase` 27; Титан `tech_fist` 18, `tech_pillar` 28 и 36).

1. Поставь `rig.tag` на каждую часть всех семи существ (`torso`, `head`, `handR`, `club`…) — отчёты станут читаемыми.
2. Исправь позы, а не проверку: руки обходят корпус (плечо выносится, локоть в сторону, хват по IK вне тела),
   дубина и посох идут мимо головы. Закрытый удар — сдвинь точку удара или предмет так, чтобы контакт был виден.
3. Задуманные перекрытия (язык во рту, пальцы на посохе внутри кисти) — в `c/<id>.studio.json` с причиной.
4. `gate all` — ноль ошибок. Предупреждения (`jump`, `weak-impact`, `thin-clip`) — разбери и либо исправь, либо
   правило с причиной.
5. Проверка: `npm run ws -- snap all --check` — эталон третьего пилота уже лежит в `tools/creatures/golden/`; список
   изменившихся кадров должен совпасть с тем, что чинили, и ни одного кадра больше. Для каждой изменившейся анимации —
   `npm run ws -- sheet <id> <anim> --against creatures-pilot-3` в отчёт. После приёмки — `snap <id>` и новый эталон
   в том же коммите.

## 2. Библиотека из семи пилотов

Цель: следующее существо собирается из готовых частей, а не пишется с нуля. Качество — как у пилота: планка
подробностей и числа приёмов остаются тестами.

1. **Типы тела** `tools/creatures/bodies/`: четвероногий тяжёлый (из `bramble_warden`), шестиногий (`gem_beetle`),
   длинный летун (`silk_dragon`), двуногий с оружием (`frost_yeti`), приземистый маг (`toad_shaman`), великан
   (`crater_titan`), крылатый дракон (`coin_dragon`). В каждом: построение скелета по пропорциям, **общий словарь
   поз** (одинаковые имена у всех: `crouch`, `lean`, `twist`, `pitch`, `stride`, `armL.*`, `armR.*`, `weapon.*`,
   `head.*`, `tail.*`…), стандартные сокеты (`handL`, `handR`, `weaponTip`, `mouth`, `footL`…), походки
   `walk_<dir>`, полёт для летунов, `life` по умолчанию, `idle`, `look`, `sleep`, `tired`, `hatch`, `turn`.
   **Позы целями, а не углами** (главное в этом пункте): ключ приёма задаётся тем, *где* должна оказаться часть, —
   `reach('handR', цель)`, `aim('weaponTip', точка пола, кадр контакта)`, `look('head', цель)`; углы плеча, локтя,
   древка считает решатель тела (аналитический IK на две кости + выбор плоскости локтя). Решатель сам обходит корпус
   и голову: проверяет руку и оружие той же мерой, что `clip` в `studio/clip.ts`, и поворачивает локоть / выносит
   плечо, пока перекрытие не уйдёт, сохраняя точку цели (допуск 1 px). Ручные углы остаются как добавка поверх для
   характера. Так руки в теле не появляются вовсе, а автор правит три цели вместо пятнадцати чисел.
2. **Шаблоны приёмов** `tools/creatures/moves/` (~10, из 28 принятых): удар сверху, таран, мах (дубина / коготь /
   хвост), залп, дыхание, прыжок с ударом, столбы из земли, рёв, призыв предмета, нырок. Шаблон = роли ключей
   (подготовка, удар, контакт, проводка, возврат) в общем словаре поз + тайминг по §7.1г + сокет контакта +
   крючки эффекта. Параметры: сила, размах, сторона, оружие, число повторов.
3. **Пресеты эффектов** `tools/creatures/fx/presets/`: лёд, лава, кристалл, споры, монеты, шёлк и ветер, колючки
   (палитра, частицы, трещины, пыль, осколки — из `-actions.ts` пилотов).
4. **`npm run ws -- new <id> --body <тип> --theme <тема> --rarity <редкость>`** — заготовка: `c/<id>.ts` на типе
   тела, `c/<id>-keys.ts` из выбранных шаблонов, `c/<id>-life.ts`, пустой `c/<id>.studio.json`, карточка-данные.
5. **Карточка данными** `c/<id>.card.json` + схема и проверка в `gate`: тип тела, пропорции, части, материалы,
   список подробностей (число по редкости), приёмы (шаблон, параметры, цепочка из пяти ответов §4.3б, образец),
   язык эффектов, сценарий `life`.
6. **Доказательство**: переведи на библиотеку двух пилотов — `bramble_warden` и `frost_yeti`.
   `snap bramble_warden,frost_yeti --check` после раздела 1: отличий нет (допуск — объяснённые единичные пиксели;
   каждый — `sheet --against` в отчёт). Остальных пятерых не трогай: `snap all --check` показывает, что их кадры
   не изменились при правке общего кода.
7. **Тест решателя**: в `test/` — рука тянется к точке за корпусом: решатель доводит кисть до цели и `worstClip`
   пуст; Йети `tech_slam` и `tech_snowball` на целях дают ноль `clip` без правил в `studio.json`.

## 3. Пробное существо быстрым путём

`storm_ram` (Грозовой баран, обычный, небесные острова, каталог §9.5) — по `references/0-quick.md`: один автор,
один критик, библиотека. Запиши в отчёт **время каждого шага по часам** и число агентов: это замер выигрыша.

- **Контрольная точка** после заготовки (карточка + форма в `idle` + ключи одного приёма, ≈ первые 20 % работы):
  один `sheet` и три строки карточки — владельцу в ответ, и работа идёт дальше, не ждёт. Если владелец остановит —
  правишь сразу, а не после полной отделки. Первые два пилота потеряли по полному кругу (1–2,5 ч) на том, что
  владелец увидел результат только в конце.
- Ключи приёмов барана — целями решателя (раздел 2.1), углы руками — только для характера.
