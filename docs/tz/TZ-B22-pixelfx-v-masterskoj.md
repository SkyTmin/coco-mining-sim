# ТЗ-Б22. Подход pixelfx — в наш инструмент

Владелец 28.11: «надо делать много картинок, в этом и будет прикол игры». Про pixelfx: «главное прокачать наш
инструмент». И уточнение: «я не говорю скопируй именно этот эффект и вставь в мою картину… я про улучшение нашего
инструмента, понимание силы всей концепции 2D-графики».

Делает Codex. Ветка от `claude/vibrant-darwin-yyjj48`, в ней уже есть `bosses-art` и библиотека. `AGENTS.md`
действует целиком.

## 0. Цель простыми словами

Тело, позы и логику движения наша мастерская делает хорошо. Слабее всё, что вокруг тела: свет, искры, дым, обломки,
вес удара. Сейчас каждый такой эффект рисуется руками заново в `c/<id>-fx.ts`. У pixelfx это решено **устройством**:
свет живёт отдельным слоем, частицы берутся из словаря, у которого уже правильная физика, цвет задаётся лестницей,
удар весит за счёт замирания, а работа идёт кругами черновиков. Нужно встроить это устройство в наш инструмент,
чтобы каждая следующая картина получала живые эффекты быстрее и лучше.

**Их готовые эффекты в картины не ставим.** Это образцы, у которых читаем хореографию и числа.

Понятия и правила описаны в `.agents/skills/pixel-bosses/references/11-fx-method.md` (дальше «§11»). Прочитай его
и `tools/creatures/vendor/pixelfx/docs/AUTHORING.md` до кода.

## 1. Что уже есть

- `tools/creatures/vendor/pixelfx/` — копия github.com/patch-gg/pixelfx, коммит `5294518`, MIT, с `LICENSE` и
  `NOTICE.md`. В ней `src/core` (рисовальщик, частицы `sim.js`, риг, действия `act.js`, цвета), 244 эффекта-образца,
  инструменты `render`/`check`/`act`/`list`. Запускается из своей папки на Node без установки. Файлы в
  `vendor/pixelfx/src` не правь.
- §11 в скилле — подход, словами.
- У нас: `fx/pen.ts` (`Pen`, `dust`, `chunks`, `fly`, `smearArc`…), слои `f.under`/`f.above`/`f.backdrop`, `lit`
  (свет тела), тряска в `engine.ts`, `kit/clock.ts` (петли целыми кругами), `ws gate`/`seam`/`sheet`/`review`.

## 2. Задачи

### Т1. Свет эффектов — отдельный слой, который прибавляется

- В `FxInput` новый `f.light: Pen`. То, что нарисовано в нём, **прибавляется** к цвету картины (сложение, а не
  наложение), сразу над `fxo` и под рамой. Запись слоя в `assets/.../frames/<anim>/` идёт рядом с остальными, а
  `compose` и просмотрщик складывают его так же.
- Набор для света: мягкое пятно (`glow`), свет вдоль линии и кольца, огонёк в точке, вспышка, которая разгорается и
  гаснет по жизни (как `Lights` у них).
- Без вызовов `f.light` картина не меняется ни на пиксель: `ws snap all --check` показывает 0 изменённых кадров.

### Т2. Словарь частиц и обломков — `fx/sim.ts`

Перенеси устройство `vendor/pixelfx/src/core/sim.js` на наш `Pen`/`Px`. Код можно адаптировать (MIT): в шапке
ссылка на источник и на `NOTICE.md`.

- Виды частиц со своим поведением: искра (вытягивается по скорости, падает, отскакивает от пола, светится), пылинка,
  тянущаяся черта, хлопья, пар, пыль, дым (освещён сверху, разбухает и тает, честно полупрозрачный), огонь (остывает
  по лестнице и переходит в дым), уголёк, звёздочка, головня, крошка (падает, отскакивает, ложится).
- Обломки: осколок, кусок, капля. Кувыркаются, отскакивают, ложатся (`rest`) и тают.
- Огоньки света — в `f.light` из Т1.
- Пол — функцией `ground(x)` из сцены картины, чтобы искры отскакивали от **нашего** стола или травы.
- **Детерминизм обязателен**: кадр `n` не зависит от того, какие кадры рендерились до него и в каком порядке.
  Симуляция идёт от нуля мелким шагом до `f.t`. Кэш снимков разрешён, но тест сверяет его результат с прогоном без кэша.
- Масштаб: у них всё рассчитано на фигурку ростом 38 px, наши питомцы 60–80 px. Скорости и размеры по умолчанию
  подбери под наш масштаб и запиши в шапке файла, какой множитель взял.
- `dust`/`chunks` из `pen.ts` не удаляй: старые картины ими пользуются.

### Т3. Лестницы цветов

- `fit(ramp, n)` — растянуть или сжать лестницу «тёмный → светлый» до `n` ступеней.
- У каждого материала в `fx/presets/materials.ts` своя лестница. Частицы и свет из Т1–Т2 принимают лестницу
  параметром: `palette: 'material:<имя>'` или массив цветов.
- В карточке существа (`card.json`) — необязательное поле `fxRamp`: язык эффектов существа одной лестницей.

### Т4. Вес удара: замирание, тряска, ответ цели

- У контакта в книге приёма (`c/<id>-keys.ts` / `card.json` → `moves`) необязательные поля: `freeze` (кадров 0–5),
  `shake` (кадров), `amp` (px).
- Во время `freeze` стоит всё: тело, эффекты (время частиц тоже стоит), предметы. Тряска идёт через уже готовую
  тряску в `engine.ts`, новую не заводи.
- По умолчанию всё 0, принятые картины не меняются.

### Т5. Проба «позы шагами»

У pixelfx конечности переходят между ключами шагами по 12 к/с, а частицы идут на 24+ к/с. Так анимация выглядит
рисованной. Сделай для клипа необязательный `poseStep: 2`: поза держится 2 кадра, всё остальное (частицы, свет,
вторичное движение на пружинах — проверь, что лучше) идёт каждый кадр. По умолчанию выключено. Решение принимает
владелец по листам Т7.

### Т6. Инструменты метода

- `ws drafts <id> <anim> --vary '<ключ>=a,b,c'` или `--seeds 1..5`: рендерит 3–5 черновиков клипа или эффекта и
  собирает **один лист рядом**, чтобы выбрать лучший (метод §11.5 п. 3).
- `ws against <id> <anim> --ref <путь|pixelfx:<id>|<другое существо>>`: наш клип и образец рядом, **в одном размере
  на экране** (§11.5 п. 5). Для `pixelfx:<id>` образец рендерит их `tools/render.mjs`.
- Их автопроверки — в `ws gate`. Добавь то, чего у нас нет:
  - одноразовый эффект не исчез к концу клипа;
  - рисование за пределами поля;
  - `Math.random` / `Date` / `performance.now` в `c/`, `fx/`, `scenes/`, `bodies/`, `kit/`;
  - кисть или кончик оружия «телепортируется» между соседними кадрами, а ключа на это нет;
  - кадр рисуется дольше порога (предупреждение; порог укажи в отчёте).

  Для 14 старых картин, которые уже не проходят общий gate, новые проверки дают только предупреждения (список в
  отчёт). Для новых картин это ошибки.

### Т7. Доказательство на деле

Сделай копию Полюсика под id `pocket_magnet_fx`. В галерею она не идёт, принятый Полюсик не меняется. Перерисуй
только эффекты обоих трюков **по §11, своими силами**, через Т1–Т4, без их готовых эффектов:

- рыбка: на касании магнита искра-крест и свет в `f.light`, на возврате в лоток 2–3 крошки и щелчок-вспышка;
- звезда: на поимке замирание 2–3 кадра, тряска 2 px, кольцо-волна по шнуру, угольки падают на стол, отскакивают,
  гаснут, и под звездой ненадолго остаётся тёплое пятно света;
- по каждому трюку минимум 3 черновика через `ws drafts`, и минимум 3 круга правки с записью «что было худшим → что
  сделал» и номерами кадров;
- листы `ws against` для пар: принятый Полюсик и `pocket_magnet_fx`; `pocket_magnet_fx` и ближайший образец pixelfx
  (например `impacts/hit-flash`, `pickups/collect-burst`);
- вариант с `poseStep: 2` (Т5) для одного трюка, лист рядом с обычным.

Владелец смотрит и решает, что переносить в настоящего Полюсика и в новые картины.

## 3. Чего НЕ делать

- Не ставить готовые эффекты pixelfx в принятые или новые картины (решение владельца 28.11). Они только образцы.
- Не менять эталоны (`golden/`) и галерею принятых картин.
- Не тянуть `pch`, Patch Desktop, их веб-галерею и шрифт. Ничего не публиковать и не ставить на ПК владельца.
- Не делать белую заливку тела на выпуске: наше правило §4.3 п. 6 (мягкая вспышка) действует. Белое допустимо только
  как свет в `f.light` (§11.7).
- Не трогать код игры `src/`.

## 4. Приёмка

Из `tools/creatures`:

```sh
npm ci
npm test                                   # + тесты: детерминизм sim (кэш = без кэша), f.light сложением, freeze, fit
npm run ws -- snap all --check             # 0 изменённых кадров у принятых картин
npm run ws -- gate pocket_magnet           # как было
npm run ws -- gate pocket_magnet_fx        # без ошибок
npm run ws -- drafts pocket_magnet_fx trick_b --seeds 1..3
npm run ws -- against pocket_magnet_fx trick_b --ref pocket_magnet
npm run verify -- --all-frames pocket_magnet_fx
```
