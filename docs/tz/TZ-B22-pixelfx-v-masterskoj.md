# ТЗ-Б22. Эффекты pixelfx в мастерской картин

Владелец 28.11: «надо делать много картинок, в этом и будет прикол игры»; про pixelfx: «это прям нужно, для прокачки
нашего инструмента, надо взять отсюда всё что можно. Главное прокачать наш инструмент».

Делает Codex. Ветка от `claude/vibrant-darwin-yyjj48` (в ней уже `bosses-art` и библиотека, см. §1). Правила
`AGENTS.md` действуют целиком. Это ТЗ про **инструмент**, а не про новое существо: после него каждая следующая картина
должна получать огонь, искры, дым, магию, подбор монет и т. п. за минуты, а не за день ручного рисования эффектов.

## 0. Цель простыми словами

Сейчас каждый эффект в картине (искра у магнита Полюсика, брызги, пыль) рисуется руками в `c/<id>-fx.ts` через `Pen`.
В pixelfx 244 готовых эффекта такого же устройства: код без картинок, детерминированный (один и тот же кадр всегда
одинаков), со слоями «за телом / перед телом» и отдельным светом. Нужно:

1. научить мастерскую вызывать любой эффект pixelfx одной строкой из `c/<id>-fx.ts`;
2. перенести в нашу проверку (`ws gate`) их автоматические проверки ошибок;
3. перенести их приём «удар продаётся телом»: замирание на контакте и тряска;
4. записать их метод работы («черновик → рендер → смотреть → чинить») в правила мастерской.

## 2. Как устроено у них и у нас (чтобы мост был правильным)

| | pixelfx | наша мастерская |
| --- | --- | --- |
| кадр | `{ w, h, ox, oy, color: Uint32Array, light: Uint32Array }` | `Px` (RGBA) и `Pen` поверх холста `@napi-rs/canvas` |
| слои | `drawBack` / `draw` | `f.under` (`fxu`) / `f.above` (`fxo`), `f.backdrop` |
| свет | отдельный буфер, складывается сверху | отдельного света у эффектов нет (`lit` — свет тела) |
| время | секунды, родные 30 к/с; «симуляции» шагают частицы 120 Гц | кадр `n / 24`, `f.t` в секундах |
| масштаб | под манекен 24 × 38 px | питомец ≈ 79 px в высоту из 128 (Полюсик) — в 2 раза крупнее |
| случайность | только `Rng(seed)` | эталоны `golden/` требуют того же |

## 3. Задачи

### Т1. Мост `tools/creatures/fx/pixelfx.ts`

```ts
pfx(f: FxInput, id: string, o: {
  at: XY | string;          // точка поля или имя сокета из f.points (например 'pole', 'weaponTip')
  start: number;            // секунда картины, когда у эффекта t = 0
  layer?: 'under' | 'above' | 'split';   // split: drawBack → under, draw → above (по умолчанию)
  scale?: 1 | 2 | 3;        // только целые, увеличение «ближайшим соседом», чтобы не ломать пиксельную сетку
  palette?: string[] | keyof typeof PAL; seed?: number; flip?: boolean; angle?: number; light?: number;
  opts?: Record<string, unknown>;        // собственные ручки эффекта из его meta.options
}): void
```

- До `start` и после конца одноразового эффекта — не рисует ничего. Петли (`meta.loop`) идут, пока их не остановят
  параметром `until`.
- **Детерминизм обязателен**: кадр `n` не зависит от того, какие кадры рендерились до него и в каком порядке
  (`verify --all-frames` и `snap` рендерят кадры поштучно и параллельно). Для симуляций (`create`) — прогон с нуля шагом
  1/120 до нужного `t`; кэшируй снимки состояния по ключу `(id, опции, seed)` и шагу, но результат обязан совпадать с
  прогоном без кэша — на это тест.
- Свет: запекай буфер `light` в цвет с альфой тем же способом, что у них в экспорте листов (`composite(frame, rgba,
  null)`), и клади в тот же слой. Отдельный слой света не заводи.
- `scale` 2 по умолчанию для питомцев высотой больше 60 px — **[предложение Claude]**, проверь на листах Т6 и напиши
  в отчёте, какой масштаб читается лучше.
- Эффект рисуется в пределах поля; что вышло за раму — обрезается (как у наших `fxu`/`fxo`).
- Палитры: в `fx/presets/materials.ts` к каждому нашему материалу добавь подходящую лестницу цветов, чтобы
  `palette: 'material:<имя>'` красил эффект в тона картины. Лестницы `PAL` из pixelfx тоже доступны по имени.

### Т2. Каталог эффектов в мастерской

- `npm run ws -- fx list <слова>` — поиск по их `tools/list.mjs` (id, название, теги).
- `npm run ws -- fx sheet <id> [--scene <сцена>] [--scale 2] [--opts '{...}']` — лист кадров **в наших условиях**:
  24 к/с, на фоне выбранной сцены из `scenes/`, с рамой. Пишет в `.studio/fx/<id>/` (в git не идёт).
- В `studio/README.md` — короткая таблица «какой эффект брать для чего» по 21 категории их каталога, с 2–3 id на
  категорию, которые ты посмотрел глазами на наших сценах.

### Т3. Их автоматические проверки — в наш `ws gate`

Перенеси из `vendor/pixelfx/tools/check.mjs` то, чего у нас нет:

| проверка | у нас |
| --- | --- |
| эффект рисует за пределами поля | ошибка |
| одноразовый эффект не исчез к концу (последний кадр не пуст) | ошибка |
| шов петли: последний кадр не переходит в первый | ошибка для `life` и петель |
| `Math.random` / `Date` / `performance.now` в `c/`, `fx/`, `scenes/`, `bodies/` | ошибка |
| медленный кадр (рендер кадра дольше порога) | предупреждение, порог в отчёт |
| ключи позы не по порядку, «телепорт» кисти между соседними кадрами | предупреждение |

Для 14 прежних картин, которые уже не проходят общий gate, новые проверки — только предупреждения (список в отчёт).
Для новых картин — как в таблице.

### Т4. «Удар продаётся телом»: замирание и тряска

- В книге приёма (`c/<id>-keys.ts` / `card.json` → `moves`) у контакта — необязательные поля `freeze` (кадров, 0–5;
  у них 0,14 с ≈ 3 кадра при 24 к/с), `shake` (кадров) и `amp` (px).
- Во время `freeze` стоят тело, эффекты (`pfx` тоже, его время не идёт) и предметы; тряска сдвигает поле через уже
  существующую тряску в `engine.ts` (не новую).
- По умолчанию всё 0: у принятых картин эталоны **не меняются** — проверь `npm run ws -- snap all --check`.

### Т5. Метод — в правила мастерской

В `studio/README.md` раздел «Эффекты: как делать», по-русски, из их `SKILL-original.md` §3 и `AUTHORING.md`:

- сначала искать готовый эффект (`ws fx list`), менять палитру/seed/ручки, и только потом писать свой;
- если направление открыто — 3–5 разных черновиков, листы всех, выбрать лучший;
- минимум три круга «рендер → смотреть лист → чинить самое плохое»; движение судить по покадровому листу, а не по
  выборке;
- таблица «что видишь → как чинить» (каша в 1×, одинокие пиксели, «ватный» удар, механичность, бледность, плоскость,
  векторный вид, шахматка вместо дыма, шов петли, эффект пропадает рывком, эффект на мёртвом теле, удар не в такт) —
  перевести и привязать к нашим 24 к/с;
- запрет: не копировать спрайты, персонажей и логотипы конкретных игр (у них то же правило).

## 4. Чего НЕ делать

- Не менять эталоны (`golden/`) принятых картин и картинки в галерее без ОК владельца.
- Не тянуть `pch`, Patch Desktop, их веб-галерею и шрифт; ничего не публиковать и не ставить на ПК владельца.
- Не дробный `scale` (1,5 и т. п.): ломает пиксельную сетку.
- Не трогать код игры (`src/`): это ТЗ только про мастерскую.
- Не править `vendor/pixelfx/src` напрямую (см. §1).
