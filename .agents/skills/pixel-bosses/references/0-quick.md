## 0. Быстрый путь партии

**Планка** — принятый третий пилот (4,5–4,8 из 5): `docs/reports/creatures/pilot-3/` (`paintings.gif`,
`<id>/painting-showreel.gif`). Новое существо не хуже ни по одному пункту.

**Инструмент** — `tools/creatures`, `npm run ws` (`studio/README.md`):
- `probe <id> <anim> <кадр>` — числа кадра; правь позы по ним, картинку смотри потом;
- `review <id> <anim>` — **цикл одного клипа**: критик, лист и стыки за один проход (вдвое быстрее трёх команд, один
  короткий ответ); `check`/`sheet`/`seam` по отдельности — когда нужен только один ответ;
- `detail <id>` — планка подробностей по кадру покоя за 1 с: **на первом кадре покоя, до клипов**;
- `sheet <id> <anim>` — один лист кадров вместо GIF; `--against <ref>` — только изменения;
- `check <id> <приём>` — автокритик одного приёма за 3–5 с: это цикл правки, полный `gate` — перед критиком;
- `gate <id>` — автокритик + подробности + числа приёмов; **зелёный `gate` — условие, чтобы звать критика**;
  `gate all` — параллельно, неизменённые зелёные существа пропускает;
- `snap <id> --check` — какие кадры изменились против эталона `golden/<id>.json`; после приёмки — `snap <id>`;
  существо без изменений во входах пропускается;
- `render <id> [--anim a,b]` — кэш, процесс на клип (одна картина на всех ядрах); тяжёлые запуски сами встают в очередь;
- галерея на GitHub Pages — `node viewer/publish-pages.mjs -m "…" --push` (без `--push` — пробный прогон);
- `.studio/ws-log.jsonl` — время и память каждой команды: что ускорять, решай по нему;
- `seam <id>` — стыки концов клипов с покоем за секунды, с частями, которые съехали (до гейта, а не в конце);
- `clip <id> <anim> --tag <часть>` — пересечения на каждом кадре клипа и запас обруча/копья/хвоста до тела.

**Не копируй из чужих файлов** — бери `kit/pet-moves.ts` (раскадровщик, рывок с перелётом, сальто с поджатием,
вращение целыми шагами, точка толчка) и `kit/clock.ts` (всё, что зависит от времени, — целыми кругами за клип)
[21.11, после Раската: одни и те же грабли у каждого питомца].

**Порядок на существо**
1. Карточка данными: тип тела, пропорции, части, материалы (5–7 тонов, фактура), список подробностей (≥ 25 / 35 / 50
   по редкости, §4.0б), приёмы — шаблон + параметры + цепочка «кто чем по чему, откуда сила, точка контакта, что
   происходит, возврат» (§4.3б), язык эффектов, сценарий `life` (§8.7). Критик принимает карточку.
2. Заготовка из типа тела и шаблонов приёмов (когда библиотека готова — `ws new`). `rig.tag` на каждой части.
3. **Референс каждой анимации набора питомца** (§4.3в, промт — `10-prompts.md`, не по памяти): аналог из жизни и его фазы в карточке → 2–3 подсмотренных примера (игры,
   мультфильмы, видео — как пример, ссылки в карточку; пишем и рисуем сами) → свой лист ключевых поз по шаблону §10.2 (картинка,
   фон `#FF00FF`) → самопроверка §10.4 и `ws sheet-lint` → владельцу вместе с контрольной точкой (шаг 4). Шаблон из библиотеки тоже сверяется с листом.
4. **Контрольная точка партии**: форма в `idle` + листы референсов + ключи одного приёма у каждого существа — один общий лист владельцу,
   работа не ждёт ответа. Остановил — правишь сейчас, а не после отделки.
5. Форма и позы → проход подробностей (`ws detail` зелёный до первого клипа) → приёмы (ключи — по листу референса, сверка `ws ref`; ключи принимаются листом `sheet` до промежуточных кадров; ключ —
   целями решателя тела: `reach`/`aim`, углы руками только для характера) → фон и рама, если тема или редкость новая.
6. `gate <id>` без ошибок. Предупреждения — либо исправить, либо правило в `c/<id>.studio.json` с причиной.
7. Критик: `sheet` и `ws ref` каждого приёма, `life`, общий `paintings.gif`; оценки 1–5 с номерами кадров (§7.2). Второй
   круг — `sheet --against`.
8. Отчёт: таблица из `gate` + короткие заметки; владельцу — сводка, `paintings.gif`, `showreel` каждого. Принятое
   владельцем — `snap <id>`, эталон в git.

**Бюджет [владелец 19.11: исполин — час и 15 % недельного лимита за одно существо]**. Куда ушло в Б3: ~34 генерации
картинок на 23 листа, из них 15 — ходьба в 8 сторон (до 3 попыток на сторону), которую библиотека и так собирает из
одного шага; 23 файла наблюдений и 23 самопроверки прозой; 7 параллельных потоков, каждый читал контекст; разовые
работы (команды студии, автомат, просмотрщик, сверка 720 кадров в браузере). Правила:
- **Листы — только на характер.** Свой лист: `idle`+`look`, оба `fidget`, `happy`, `trick`, `sleep_in`+`sleep_out`,
  `wake_startled`+`hatch`, каждый приём. Короткие клипы — по 2–3 клетки на одном листе (≤ 6 клеток). Без листа —
  из типа тела библиотеки: `walk_<dir>`, `turn`, `tired`, `sleep`; лист ходьбы (один, сбоку) — только для нового типа
  тела. Обычный и необычный ≈ 8 листов вместо 23.
- **Наблюдения — из [общей библиотеки движений](motions/README.md)** (радость, трюк, сон, жесты, шаг по типам тела,
  приёмы по шаблонам); своё — только то, чем существо отличается, 3–5 строк в карточке. Новые примеры из интернета —
  когда в библиотеке нет похожего движения.
- **Проза — короче**: самопроверка — таблица «клетка: да/нет и что не так», не абзацы; отчёт партии ≤ 6 КБ.
- **Команда**: на существо один автор (все его клипы подряд), критик — два прохода на существо (все листы сразу; итог `showreel` + `life`);
  сборщик — на низком усилии. Без параллельных потоков внутри одного существа.
- **Разовое не повторять**: сверка просмотрщика в браузере, тесты на телефоне — только когда меняется код просмотрщика.
- **Большое не читать целиком** [19.11]: код рисования «Каторги» — 92 тыс. строк (`f1-art.ts` — 9,6 тыс.),
  наши `meta.json` / `ref.json` / `atlas.json` — сотни КБ. Переносить копированием (`cp`), читать шапку и нужные
  функции по номерам строк (`grep -n` → `sed -n`), вывод тестов и сборки — хвостом (`tail`), большие JSON не печатать.
