# Живые картины

Требуется Node.js 22 или новее. Команды запускаются в `tools/creatures`.

```sh
npm ci
npm test
npm run render -- --id bramble_warden
npm run render -- --id bramble_warden --anim idle --scale 3
npm run verify -- --all-frames bramble_warden
```

Имя техники берётся из `animations` нужного существа. По умолчанию рендерятся все анимации, золотые версии покоя и первого приёма. Число в `--scale` задаёт только размер GIF. PNG всегда в исходной пиксельной сетке. Для совместной поставки вариантов одного существа применяйте один масштаб.

Модель в `c/<id>.ts` экспортирует `Creature` из `types.ts`. Риг получает сторону 0–15, нулевая соответствует авторскому повороту в три четверти. `anchor`, `eye` и `points` измеряются в локальных пикселях спрайта. В `effects` те же точки уже перенесены в координаты поля. Для следа, дуги или снаряда `pointAt(time,name)` возвращает точку на момент выпуска. Контакты в исходнике задаются в секундах, в `meta.json` лежат номера кадров с нуля. Слои эффектов рисуются оригинальным `Pen`.

`compose(creature, scene, border, anim, frame/24, side, variant)` возвращает готовую картину в `picture`, исходный кадр тела в `body` и RGBA-буферы в `layers`. У каждого `Px` есть ширина `w`, высота `h` и `data` в порядке RGBA. Файл сцены из `scenes/` и профиль редкости из `frames/` экспортируют функции или объект по умолчанию согласно `types.ts`.

Главная анимация `life` длится 12–16 секунд. План маршрута в `c/<id>-life.ts` задаёт длину полного шага в финальных мировых пикселях, исходный yaw и последовательность остановок и движений. Координата `at` — положение ног на поле в начале сегмента (доли ширины/высоты). Шёлковый пролетает соседние точки по сплайну с переменной высотой. Для движения игры есть отдельные `walk_n`, `walk_ne`, `walk_e`, `walk_se`, `walk_s`, `walk_sw`, `walk_w`, `walk_nw`. Демонстрационный односекундный GIF проходит один шаг и начинает его снова. Игра продолжает маршрут, прибавляя смещение цикла к исходной точке ног. В `meta.json` для каждого направления записаны вектор скорости в пикселях поля за секунду, начальная точка ног и шаг в мире.

Кадры для игры рендерятся в `assets/creatures/<id>/`. Сгенерированные PNG и GIF поставляются через Release. Для каждого кадра `frames/<anim>/motion.json` содержит фактическую точку ног в координатах поля, отдельный сдвиг камеры, номер кадра фона, сторону корпуса и головы, позу, высоту полёта и объявленные опорные стопы. При сборке берите фон `frames/<anim>/bg/NNN.png`, когда он есть, иначе `bg/loop/` по номеру `backgroundFrame` из этого трека. Маски предметов хранятся в `bg/front/<id>.png`, их глубина — в `bg/front-depth.json`, общий вид — в `bg/front.png`. После сдвига камеры предметы, чья глубина меньше либо равна высоте ног, рисуются позади модели. Затем идут слои `fxu`, `body`, `lit`, `fxo`, оставшиеся передние предметы, рама и `over` (у show/peek). Размер каждого PNG совпадает с размером картины с рамой. `compose` выполняет ту же сортировку и наложение. При увеличении GIF сохраняет единую сетку пикселей, а неподвижные области непрозрачных картин наследуются из предыдущего кадра.

Исходные `Rig`, `F3`, `Px`, функции поз и пиксельных эффектов перенесены из [SkyTmin/coco-instruments](https://github.com/SkyTmin/coco-instruments/tree/523bae1fdc0e06052648a3c3d09e9f1642ca615d). В комментариях указаны исходные файлы, лицензия MIT приложена в `rig/LICENSE`. Тест паритета сверяет кадр жука-копилки с независимым снимком веб-стенда. Команда `verify` проверяет экспортированные файлы, размеры, тайминг каждого кадра GIF и сверяет декодированные кадры контактов и переходов с их исходными PNG-слоями.

Ключ `--all-frames` сверяет каждый кадр каждой картины со всеми PNG-слоями и заново отрисованными исходниками, включая золотые варианты.

Для точного повторения второго пилота используйте тег `creatures-pilot-2`. В нём команда `npm run gallery` собирает стену, линейку и ряд рам.

## Повторный пилот

Восемь `walk_<dir>` показывают сдвиг за один цикл шага. Скорости в метаданных заданы для сетки поля, точки опоры привязаны к той же сетке. Сценарии `c/<id>-life.ts` ведут существо между точками по полу в течение 12–16 секунд. У предметов переднего плана есть собственная глубина. При склейке `compose` сравнивает её с координатой ног, поэтому один и тот же предмет может оказаться за существом или перед ним. Для снятия отдельных стоп используйте имена сокетов из `planted`.

Для воспроизведения всей партии выполните команды из `tools/creatures`. Архив содержит GIF ×3, нативные PNG всех слоёв, глубины, траектории, семь комплектов рам и метаданные. Предпросмотры в отчёте используют нативный масштаб и сохраняют хронометраж 24 к/с.

```sh
npm ci
npm test
for id in bramble_warden gem_beetle silk_dragon frost_yeti toad_shaman crater_titan coin_dragon
do
  npm run render -- --id "$id"
  npm run verify -- --all-frames "$id"
done
npm run gallery
python3 release.py /tmp/creatures-pilot-2.zip
```

## Третий пилот. Приёмы

В книге `c/<id>-keys.ts` записаны позы приёма, имя физической точки для эффекта и номера кадров при 24 к/с. Автор готовит 4–6 поз, и критик сверяет их на листе до включения интерполяции. Скрипт измерений берёт силуэт из слоя тела, а точки рождения эффектов и пиксели следа из рисовальщика. Порог зависит от выбранного движения «Каторги». Команды выполняются из `tools/creatures` после `npm ci`. В `meta.json` поле `showreel` перечисляет главы, начало и длина которых заданы в кадрах с нуля. Между главами шесть кадров покоя. В отчётной копии под картиной видны номер и название приёма. Полный GIF ×3 в архиве сохраняет размер рамы.

```sh
npm test
for id in bramble_warden gem_beetle silk_dragon frost_yeti toad_shaman crater_titan coin_dragon
do

  npm run verify -- --all-frames "$id"

node --import tsx tech-metrics.ts
```
