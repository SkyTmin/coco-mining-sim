# Мастерская (`npm run ws`)

Быстрый цикл для авторов и критиков существ. Всё запускается из `tools/creatures` после `npm ci`.

| Команда | Что делает | Время (4 ядра) |
|---|---|---|
| `npm run ws -- new <id> --body <тип> --theme <сцена> --rarity <редкость>` | Создаёт модель, ключи приёмов, маршрут, настройки мастерской и карточку. Параметры `--moves ram,volley`, `--effects` и `--name` выбирают шаблоны, эффекты и имя. Существующие файлы сохраняются | < 1 с |
| `npm run ws -- check <id\|all> [anim…] [--errors]` | автокритик по каждому кадру: руки и оружие в теле (`clip`), тонкие стержни в теле (`thin-clip`), удар закрыт предметом переднего плана (`hidden-contact`), щелчок в позу покоя на последнем кадре (`end-pop`), скачок силуэта между соседними кадрами (`jump`), эффект удара сливается с полом (`weak-impact`), стоящая нога едет по полу в боковой ходьбе (`foot-slide`), названная часть пропала из вида за корпусом или головой на ударе (`part-gone`, нужен `rig.tag`) | 3–43 с на существо; один приём — 3–5 с |
| `npm run ws -- gate <id\|all> [--jobs N] [--force]` | `check` + планка подробностей (§7.1в) + числа приёмов (§7.1г); код выхода 1 при ошибке. Зелёный `gate` — условие, чтобы звать критика. Несколько существ — параллельно; зелёный результат запоминается, и существо без изменений во входах не проверяется снова | все семь — 60 с на 4 ядрах вместо 2 мин 45 с подряд; зелёное без изменений — 0,7 с вместо 5–75 с (красные проверяются всегда) |
| `npm run ws -- probe <id> <anim> <кадр>` | числа одного кадра без картинки: ноги, рамка тела, центр, все сокеты в координатах поля, точки рождения эффектов, самые глубокие перекрытия рига с именами частей | 1–2 с |
| `npm run ws -- ref <id> <anim> [sheet.png --grid 3x2 --frames 0,8,16,24,32,40] [--out file.png]` | Сопоставляет клетки оригинального рисунка с кадрами, выводит IoU и ошибки сокетов. Сохраняет лист сравнения в `.studio/` | по числу ключей |
| `npm run ws -- sheet <id> <anim> [--frames a,b] [--every N] [--scale k]` | один PNG ≈ 1 Мп: ключи (синий), контакты (жёлтый), кадры с ошибками (красная рамка) и предупреждениями (оранжевая), несколько промежуточных; обрезка по действию | 3–8 с |
| `npm run ws -- sheet <id> <anim> --against <git-ref>` | только изменившиеся кадры: старый над новым (рендер старой версии через `git worktree`) | 5–10 с |
| `npm run ws -- render [id…\|all] [--jobs N] [--force]` | `render.ts` параллельно по существам; существо без изменений во входных файлах пропускается (`assets/creatures/<id>/.ws-render.json`) | все семь — 2 мин 37 с вместо ~8,7 мин подряд; без изменений — < 1 с |
| `npm run ws -- snap <id\|all> [anim…]` | эталон: короткий хэш каждого кадра каждой анимации (с `life` и `showreel`) в `tools/creatures/golden/<id>.json`, лежит в git | все семь — 72 с, 10 026 кадров, 133 КБ |
| `npm run ws -- snap <id\|all> [anim…] --check` | сравнить с эталоном: какие кадры каких анимаций изменились; код выхода 1 при отличии. Доказательство рефакторинга одной командой, без старых веток | все семь — 72 с |

Листы ложатся в `tools/creatures/.studio/` (в `.gitignore`).

## Порядок работы

1. Меняешь позу — сначала `probe` (числа), потом `check <id> <приём>` (3–5 с), потом `sheet` (одна картинка), GIF —
   только в конце. Полный `gate` — один раз перед критиком.
2. Перед критиком — `gate <id>` без ошибок.
3. Критик открывает `sheet` каждого приёма (и `--against` на втором круге), а не GIF целиком.
4. Меняешь общий код или переносишь существо на библиотеку — `snap all --check`: изменились только те кадры, которые
   ты хотел изменить. Принятое владельцем существо — `snap <id>` и коммит `golden/<id>.json` вместе с работой.

## Карточка и ключи нового существа

В `c/<id>.card.json` автор задаёт пропорции, материалы, видимые подробности, маршрут и механику каждого приёма. Схема лежит в [card.schema.json](card.schema.json). Заготовку можно увидеть через `sheet` сразу. Перед приёмкой `gate` проверяет число подробностей по редкости, пять ответов на каждый удар, эталон, фактические анимации, сокеты и маршрут.

В ключах координаты цели задаются относительно стоп тела в порядке «вперёд, вправо, вверх». Нулевая высота соответствует земле. Кисть ведёт `reach`, оружие — `aim`, голову — `look`. Вращение ракурса и перевод в пиксели выполняет тело. [Пример с ключами и своим обликом](../README.md)

## Имена частей

`clip` и `probe` называют части по `rig.tag`. Поставь перед построением части `r.tag = 'handR'`
(`'torso'`, `'head'`, `'club'`…) — отчёт станет «handR in torso» вместо «cap #737a8b r2 in ell #c1cccd».

## Задуманные перекрытия

`c/<id>.studio.json` (необязателен):

```json
{
  "clipAllow": [{ "a": "tongue", "b": "head" }],
  "partGone": [
    {"part": "coffer", "anim": "tech_dive", "frames": [30, 36], "reason": "При выходе из насыпи первой показывается морда, сундук ещё внизу."}
  ],
  "skip": { "jump": ["show:74-77"], "weak-impact": ["tech_croak"] }
}
```

`clipAllow` сравнивает подстроки имени части (тега) или метки; `partGone` задаёт полное имя части, анимацию, включительный диапазон кадров и причину. Строка старого формата, например `"tongue"`, совпадает с подстрокой имени во всех анимациях. `skip` — анимация или `анимация:кадр-кадр`.
Каждое правило — с причиной в отчёте; владелец принимает итог глазами.

## Как устроены проверки

- `clip`: ось капсулы (рука, древко, хвост) входит в крупный эллипсоид (корпус, голова) глубже 0,55 его
  нормированного радиуса и на 0,3 глубже, чем в позе покоя (`idle`, первый кадр анимации, второй облик после
  `phase`). Капсулы тоньше 1,5 единицы рига — предупреждение.
- `hidden-contact` измеряет, какую часть окна 5×5 вокруг точки удара закрывает передний план. Проверка переносит координаты с поля на картину с учётом рамы и дрожания камеры. Если предмет закрывает больше половины окна, это ошибка. При нескольких попаданиях проверяется сокет, назначенный именно этому кадру.
- `jump`: доля силуэта, сменившаяся между соседними кадрами, больше 30 % и больше пяти медиан анимации; окно
  удара (4 кадра до контакта) не проверяется. `end-pop` — такой скачок на последнем кадре разовой анимации.
- `foot-slide`: в `walk_e` / `walk_w` нога (сокеты `footL`, `hindR`, `foreL`, `legL2`…) в нижней точке своего шага
  сдвигается больше чем на 1 пиксель между кадрами. У семи принятых пилотов — 0 пикселей.
- `part-gone`: в окне удара (4 кадра до контакта и 2 после) часть с именем `rig.tag` видна меньше чем на 25 % своей
  площади, хотя в позе покоя была видна хотя бы на 75 %, и закрывает её тело (`torso`, `body`, `chest`, `belly`,
  `head`, `neck`…), а не другая рука. Это «рука ушла в тело» так, как видит зритель, включая кулак за корпусом без
  касания (`clip` такое не видит). Существа без `rig.tag` пропускаются: по одному примитиву видимость ничего не
  значит — пушистая рука Йети состоит из десятка перекрытых комков.
- Порядок частей — по глубине каждого пикселя, фиксированных слоёв нет (скилл, `2-pipeline.md` §2.2б).
- `weak-impact`: медиана разницы яркости пикселей эффекта и пола под ними в 8 кадрах после контакта меньше 12.


- `from-nowhere` запоминает первый видимый кадр каждого материального предмета. Когда хотя бы один его пиксель виден, расстояние от ближайшего края нарисованного предмета до физического сокета или до линии пола на его глубине должно быть не больше **6 px**. При рождении залпа соседний снаряд может закрывать край, касающийся пасти. Сокеты с суффиксом `Floor` или `Ground` служат проекциями на землю. При переходе из 3D в 2D сохраняют идентификатор, например `rig.tag = 'material:snowball'` и `paintMaterial(..., 'snowball', ...)`. Студия учитывает пиксели этой части, выигравшие тест глубины. Тень и траектория сами по себе не доказывают появления снаряда. Для 2D-предмета художник оборачивает в `paintMaterial` его обычную кисть на всех фазах, включая набор, удержание, полёт, и сохраняет одно имя. Если материал скрыт телом, передним планом или более поздней краской, проверка ждёт первого видимого пикселя. Объявленное попадание снаряда без единого видимого предмета — ошибка.
- `reach` проверяет в контакте указанную в `reachHand` ведущую руку при махе, тычке или ударе сверху. Прямая от плеча до запястья должна быть **строго длиннее 80 %** суммы длин плечо–локоть и локоть–запястье. Все три точки берутся из того же 3D-рига в позе удара. Отсутствующие суставы у назначенной руки — ошибка.
- `face-at-contact` требует хотя бы **1 пиксель** глаза на кадре каждого контакта, включая приземление снаряда. Проверка считает размеченные примитивы глаза, которые выдержали тест глубины и видны после наложения переднего плана и эффектов.

Для намеренного появления из облака указывают в `c/<id>.studio.json` точное имя предмета, анимацию, кадр появления и причину. Для разворота спиной в кадре удара указывают анимацию, кадр и причину. Название каждой фазы и её кадр фиксированы. Для одной последовательности с общей причиной можно перечислить точные пары в `"appearances": { "drop-1": 8, "drop-2": 12 }` вместо полей `object` и `frame`.

```json
{
  "contactAllow": [
    { "kind": "from-nowhere", "anim": "tech_rain", "frame": 8, "object": "drop-2", "reason": "Капля отделяется от нарисованного облака." },
    { "kind": "face-at-contact", "anim": "tech_tail", "frame": 19, "reason": "Удар хвостом выполняется спиной к зрителю." }
  ]
}
```

## Сравнение с рисунком приёма

Лист рисуют до постановки ключей. Камера видит существо под тем же углом, клетки читаются слева направо по строкам. Автор отмечает на исходном PNG опору и анатомические точки. Размерности — пиксели **внутри клетки**, отсчёт от её верхнего левого угла. Нижнюю полосу отводят под подписи. В файле `c/<id>.ref.json` каждому приёму соответствует отдельная запись. Пример структуры для двух клеток:

```json
{
  "tech_snowball": {
    "sheet": "../../../docs/reports/creatures/b2b/references/frost_yeti/snowball.png",
    "grid": [2, 1],
    "frames": [0, 32],
    "idleHeight": 160,
    "captionHeight": 24,
    "keys": [
      { "ground": [110, 192], "points": { "handL": [94, 112] } },
      { "ground": [110, 192], "points": { "clubTip": [196, 115], "projectile:snowball": [196, 115] } }
    ]
  }
}
```

- `sheet` указывает на версионируемый PNG относительно папки `c/`. `frames` сопоставляет клетки со временем проигрывателя при 24 кадрах/с, включая задержку на ударе. Для зарегистрированного листа хватает `npm run ws -- ref <id> <anim>`. Для проверки заведомо другой позы передайте другой `--frames` в том же порядке клеток.
- `idleHeight` — высота полного силуэта исходной стойки со снаряжением в масштабе художника. Все клетки масштабируются одним коэффициентом: высота родного `idle` в пикселях, делённая на `idleHeight`. `ground` обозначает пол под стойкой, включая кадры над землёй. Опора совмещается с полом картины с учётом положения персонажа, рамы и дрожания камеры. Так присед, подъём оружия и высота прыжка сохраняются. При разовой проверке листа без разметки положите в первую клетку стойку `idle`: программа использует её рост и нижний след стоп как общую калибровку.
- `captionHeight` — высота нижней полосы в пикселях; по умолчанию отрезается 12 % клетки. Фон снимается поканально с допуском 42 от `#FF00FF`. Порог покрытия для силуэта равен 128/255. IoU — площадь пересечения силуэта персонажа и рисунка, делённая на площадь их объединения. В силуэт входят оружие и видимые размеченные физические предметы. Искры, дуги и фон отделены рендером. Части рисунка за пределами картины тоже попадают в объединение.
- `points` необязателен. Ключ — имя сокета из `ws probe` либо `projectile:<id>` для предмета в руке или в полёте. Число под клеткой — евклидово расстояние от спроецированного сокета или центра снаряда до метки художника в родных пикселях картины. Пропавшая точка даёт `MISSING` и ошибку в `gate`.
- Слева — кадр в окружении, в центре — рисунок, справа — его бирюзовый контур поверх кадра. Бирюзовый круг показывает цель, золотой квадрат и отрезок — фактическое положение и величину промаха. Все панели одного листа используют общий масштаб и высоту пола. Команда `ref` сохраняет диагностику при любом результате. `gate` проверяет каждую клетку и запоминает зелёный результат до изменения входов, включая содержание файла PNG и разметки.
- `gate` требует **IoU ≥ 0,60 и ошибку каждой точки ≤ 18 родных пикселей** на каждом ключе. Единые границы получены по 24 клеткам четырёх исправленных приёмов Йети и Квакуньи. У старой версии этим условиям соответствовала одна клетка из 24 — исходная стойка Йети. Подмена кадров замаха и контакта в `tech_slam` даёт ошибку конца оружия более 150 px. Перед изменением границ приложите оба листа сравнения в [отчёт Б2б](../../../docs/reports/creatures/b2b/REPORT.md).
- Проверка инструмента запускается через `node --import tsx --test test/ref.test.ts`. Пиксельный контроль совпадающей позы даёт IoU 1. У клетки с силуэтом 4×2 над землёй против стоящего 4×5 значение равно 0,4. Тест с настоящим кадром тарана сравнивает контакт с тем же рисунком и затем подставляет исходную стойку.

### Исходный облик, проверка и подписи листов поз

Из `tools/creatures`:

```sh
npm run ws -- export-ref meadow_colossus idle 0
npm run ws -- sheet-lint poses.png --grid 3x2 --ref .studio/meadow_colossus-idle-0-ref.png --air 3,4
npm run ws -- sheet-lint sleep-io.png --grid 3x2 --low 3,4,5   # присед, поклон, лёжа: рост не сравнивается, линия ступней — да
npm run ws -- label poses.png --grid 3x2 --roles 'стойка;сжатие;взлёт;вершина;опора;возврат'
```

`export-ref` сохраняет слои `body` и `lit` указанного кадра без окружения и эффектов, с полем чистого `#FF00FF`. Каждый пиксель оригинала занимает блок 4×4. По умолчанию это `idle` и кадр 0. Файл попадает в `.studio/<id>-<anim>-<frame>-ref.png`, путь можно задать через `--out`.

`sheet-lint` принимает исходный PNG **до подписей**. Клетки нумеруются с 1, по строкам слева направо. Ошибка даёт код выхода 1. Для машиночитаемого отчёта используйте `npm run -s ws -- sheet-lint … --json`. В отчёте по каждой клетке есть границы видимого тела, площади отдельных пятен, доля точного фона, примеси, кайма и доля чужих цветов при наличии эталона.

При броске реквизита укажите клетки его свободного полёта, например `ws sheet-lint trick.png --grid 3x2 --air 2,3 --prop 2,3`. Числа начинаются с единицы. В этих клетках инструмент проверяет персонажа и один отделившийся предмет, включая контур, палитру и запас до границы у каждого.

- Силуэт связан по 8 соседям. Главная компонента больше 12 пикселей. Дополнительная компонента больше 12 пикселей, прозрачность, тонированный фон или отступ тела меньше 4% дают ошибку.
- Рост и высота линии ступней измеряются в долях высоты клетки. За образец берётся первая наземная клетка, допустимое изменение каждого замера ±12%. В `--air` указывают **только** клетки прыжка. Для них сохраняются проверки отступа, состава рисунка и цветов.
- На контуре программа ищет смесь пурпура с соседним цветом тела. Допустимая доля каймы 2%. Чужие относительно `--ref` цвета могут занимать до 5% тела. Для сравнения близких оттенков допустима среднеквадратическая разница 16 по RGB и разница до 24 в каждом канале.
- `label` добавляет отдельную полосу под каждой строкой и переносит длинные подписи. По умолчанию пишет `poses.labeled.png`, явный путь принимается через `--out`. Исходник сохраняет все пиксели. Программа печатает `captionHeight` для регистрации подписанного листа в `<id>.ref.json`; у исходного листа с рисунком без подписей укажите `captionHeight: 0`.

## Новая картина-питомец

Набор включает `idle`, два жеста `fidget_a/b`, восемь `walk_<dir>`, взгляд `look`, радость `happy`, игру `trick`, приёмы своей редкости, три клипа сна, `wake_startled`, `hatch`, `turn` и `tired`. У каждого самостоятельного клипа есть свой рисунок с позами и запись в `c/<id>.ref.json`. Студия измеряет совпадение с рисунком и сверяет силуэт двух крайних кадров каждого разового клипа с покоем на тех же координатах. Для стыка требуется IoU ≥ 0,90.

Маршрут, частоты и реакции задаются в `assets/creatures/<id>/behavior.json` по схеме `bodies/behavior.schema.json`. Точки остановок берутся из `life.beats[].at` карточки. Прогулки занимают 35–50 % времени, обычные атаки начинаются с интервалом 30–45 секунд. Прерывания указываются в кадрах при 24 кадрах/с, интервал между ними — не более семи кадров. Касание запускает радость, двойное касание — трюк, касание во сне — испуг и затем радость. Один автомат управляет показом в браузере и тридцатисекундным экспортом с фиксированным зерном.

Чтобы открыть стену локально, из `tools/creatures` выполните `python3 -m http.server 8000 --directory viewer` и откройте `http://localhost:8000/`. Статический сервер также может раздавать содержимое архива `viewer.zip` из Release.

После обычного рендера `meadow_colossus` атласы стены можно пересобрать из корня репозитория:

```sh
python tools/creatures/viewer-atlas.py meadow_colossus
python -m http.server 8000 --directory tools/creatures/viewer
```

Для просмотра готовой стены достаточно второй команды. Откройте `http://localhost:8000/` в браузере.

Для общего листа нескольких клипов в `c/<id>.ref.json` укажите одинаковые `sheet` и `grid`. Поле `cells` выбирает клетки для конкретного клипа в том же порядке, что `frames` и `keys`. Нумерация начинается с нуля и идёт по строкам, например `[3,4,5]` выбирает второй ряд сетки 3×2. Без `cells` команда берёт клетки с начала листа. В `c/<id>.studio.json` массив `bodyClips` отмечает движения, полученные от типа тела: восемь направлений шага, разворот, усталость и петлю дыхания во сне. Проверки наличия клипов, стыков и опор продолжают действовать. Если `sleep` наследуется, конец `sleep_in` и начало `sleep_out` и `wake_startled` сверяются с первым кадром `sleep` при том же пороге IoU 0,90.
