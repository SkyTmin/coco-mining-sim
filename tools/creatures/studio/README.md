# Мастерская (`npm run ws`)

Быстрый цикл для авторов и критиков существ. Всё запускается из `tools/creatures` после `npm ci`.

| Команда | Что делает | Время (4 ядра) |
|---|---|---|
| `npm run ws -- check <id\|all> [anim…] [--errors]` | автокритик по каждому кадру: руки и оружие в теле (`clip`), тонкие стержни в теле (`thin-clip`), удар закрыт предметом переднего плана (`hidden-contact`), щелчок в позу покоя на последнем кадре (`end-pop`), скачок силуэта между соседними кадрами (`jump`), эффект удара сливается с полом (`weak-impact`), стоящая нога едет по полу в боковой ходьбе (`foot-slide`) | 3–43 с на существо; один приём — 3–5 с |
| `npm run ws -- gate <id\|all> [--jobs N] [--force]` | `check` + планка подробностей (§7.1в) + числа приёмов (§7.1г); код выхода 1 при ошибке. Зелёный `gate` — условие, чтобы звать критика. Несколько существ — параллельно; зелёный результат запоминается, и существо без изменений во входах не проверяется снова | все семь — 60 с на 4 ядрах вместо 2 мин 45 с подряд; зелёное без изменений — 0,7 с вместо 5–75 с (красные проверяются всегда) |
| `npm run ws -- probe <id> <anim> <кадр>` | числа одного кадра без картинки: ноги, рамка тела, центр, все сокеты в координатах поля, точки рождения эффектов, самые глубокие перекрытия рига с именами частей | 1–2 с |
| `npm run ws -- sheet <id> <anim> [--frames a,b] [--every N] [--scale k]` | один PNG ≈ 1 Мп: ключи (синий), контакты (жёлтый), кадры с ошибками (красная рамка) и предупреждениями (оранжевая), несколько промежуточных; обрезка по действию | 3–8 с |
| `npm run ws -- sheet <id> <anim> --against <git-ref>` | только изменившиеся кадры: старый над новым (рендер старой версии через `git worktree`) | 5–10 с |
| `npm run ws -- render [id…\|all] [--jobs N] [--force]` | `render.ts` параллельно по существам; существо без изменений во входных файлах пропускается (`assets/creatures/<id>/.ws-render.json`) | все семь — 2 мин 37 с вместо ~8,7 мин подряд; без изменений — < 1 с |
| `npm run ws -- snap <id\|all> [anim…]` | эталон: короткий хэш каждого кадра каждой анимации (с `life` и `showreel`) в `tools/creatures/golden/<id>.json`, лежит в git | все семь — 72 с, 10 026 кадров, 133 КБ |
| `npm run ws -- snap <id\|all> [anim…] --check` | сравнить с эталоном: какие кадры каких анимаций изменились; код выхода 1 при отличии. Доказательство рефакторинга одной командой, без старых веток | все семь — 72 с |

Листы ложатся в `tools/creatures/.studio/` (в `.gitignore`).

## Порядок работы

1. Меняешь позу — сначала `probe` (числа), потом `check <id> <приём>` (3–5 с), потом `sheet` (одна картинка), GIF —
   только в конце. Полный `gate` — один раз перед критиком.
2. Перед критиком — `gate <id>` без ошибок.
3. Критик открывает `sheet` каждого приёма (и `--against` на втором круге), а не GIF целиком.
4. Меняешь общий код или переносишь существо на библиотеку — `snap all --check`: изменились только те кадры, которые
   ты хотел изменить. Принятое владельцем существо — `snap <id>` и коммит `golden/<id>.json` вместе с работой.

## Имена частей

`clip` и `probe` называют части по `rig.tag`. Поставь перед построением части `r.tag = 'handR'`
(`'torso'`, `'head'`, `'club'`…) — отчёт станет «handR in torso» вместо «cap #737a8b r2 in ell #c1cccd».

## Задуманные перекрытия

`c/<id>.studio.json` (необязателен):

```json
{
  "clipAllow": [{ "a": "tongue", "b": "head" }],
  "skip": { "jump": ["show:74-77"], "weak-impact": ["tech_croak"] }
}
```

`clipAllow` сравнивает подстроки имени части (тега) или метки. `skip` — анимация или `анимация:кадр-кадр`.
Каждое правило — с причиной в отчёте; владелец принимает итог глазами.

## Как устроены проверки

- `clip`: ось капсулы (рука, древко, хвост) входит в крупный эллипсоид (корпус, голова) глубже 0,55 его
  нормированного радиуса и на 0,3 глубже, чем в позе покоя (`idle`, первый кадр анимации, второй облик после
  `phase`). Капсулы тоньше 1,5 единицы рига — предупреждение.
- `hidden-contact`: в кадре контакта больше половины окна 5×5 вокруг точки рождения эффекта закрыто слоем `bgf`.
- `jump`: доля силуэта, сменившаяся между соседними кадрами, больше 30 % и больше пяти медиан анимации; окно
  удара (4 кадра до контакта) не проверяется. `end-pop` — такой скачок на последнем кадре разовой анимации.
- `foot-slide`: в `walk_e` / `walk_w` нога (сокеты `footL`, `hindR`, `foreL`, `legL2`…) в нижней точке своего шага
  сдвигается больше чем на 1 пиксель между кадрами. У семи принятых пилотов — 0 пикселей.
- `weak-impact`: медиана разницы яркости пикселей эффекта и пола под ними в 8 кадрах после контакта меньше 12.
